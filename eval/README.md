# 《原神》钟离 NPC 微调评测套件 V1

本项目用于**模型已训练完成**的阶段，比较同一基础模型在 LoRA 微调前（Before）与微调后（After）的角色对话表现。不会自动构建训练集，也不会声称已经完成真实 H100 推理。当前测试题为根据任务及所提交 471 条训练样本的构成专门拟定，**尚需人工核查与冻结**。

## 为什么要这样设计

实际上传的训练语料共有 **471** 条 JSONL，全部可解析；`grounded_adaptation` 剧情接续 **410** 条，`direct` 语音类 **61** 条；类别为 `lore` **442**、`daily` **23**、`values` **6**、`boundary` **0**。其中剧情对话常以“请以钟离的身份接续下面的对话……”为用户请求格式。

这种训练数据容易提升剧情接话能力，却不必然提升开放式闲聊或越界处理。因此设置不同的测试分组，而不把简单“台词重现率”当成角色泛化能力。

## 文件说明

- `data/eval_single.jsonl`：36 条独立的单轮候选题目（daily 10 / lore_values 10 / boundary 8 / context 8），每条含 `reviewer_focus` 供人工参照；生成脚本**只会向模型输入 `user` 字段**。
- `data/eval_multi.jsonl`：4 个多轮场景，每组包含 3 个依次输入的用户消息。
- `scripts/generate.py`：对同一基础模型分别调用原始模型与 LoRA adapter，使用一致的 system prompt、非思考模式、贪心解码与最大输出长度。
- `scripts/build_blind.py`：按场景随机将 Before/After 分配到 A/B；输出需要人工填写的盲评分表以及需要保密的映射文件。
- `scripts/summarize.py`：校验分数范围并汇总各维度和各类别的 Before/After 均分、配对胜平负、代表案例索引。
- `REPORT_TEMPLATE.md`：可直接用于面试作业报告的评测章节模板。

## 运行流程

请使用已经成功训练的 Python 环境，依赖 `torch`, `transformers`, `accelerate`, `peft`。如果尚未安装：

```bash
pip install torch transformers accelerate peft
```

### 1. 人工审核并冻结测试集

在训练结束后确定测试集，不再根据 After 的表现来删题、改题。对比 `data/eval_single.jsonl`、`data/eval_multi.jsonl` 与所有训练、验证样本；不能出现重复题目、同一段剧情的改写版，或模型训练时见过的目标回复。相同主题（例如“契约”）可以出现在训练和测试中，但不得高度复刻同一训练示例。若发现重合，在**首次运行任何模型评测之前**一次性替换并记录变更。

评测集生成之前建议运行词面相似度筛查：

```bash
python scripts/check_overlap.py --train /绝对路径/你们实际用于训练的.jsonl
```

该检查只会标记可能重复的提问，不能替代人工判断跨场景的语义重合。当前候选题已与这次上传的 471 条训练样本进行了初步词面重合检查，阈值为 0.72，未触发警报；**但这不意味着已经排除了语义泄漏，且你们应使用实际训练时的文件复查**。

### 2. 生成 Before

```bash
python scripts/generate.py \
  --variant base \
  --model-id Qwen/Qwen3-14B \
  --output-dir results
```

### 3. 生成 After

```bash
python scripts/generate.py \
  --variant finetuned \
  --model-id Qwen/Qwen3-14B \
  --adapter /绝对路径/你的lora_adapter \
  --output-dir results
```

**注意**：以上模型名只是先前讨论的建议示例，不代表你们实际训练用的版本。务必换成你们真实训练时的基础模型**相同的模型 ID/修订版本**。如果训练的是全量 checkpoint、或模型为 Qwen3.5 多模态架构，需要按实际架构调整加载逻辑；不能照搬本纯文本 LoRA 脚本。

`generate.py` 使用与本项目 v2 训练配置一致的统一 system prompt：

> 你正在扮演《原神》中的钟离。请依据角色已有设定与说话方式自然回应；不确定的设定不要编造。

设定 `enable_thinking=False`、`do_sample=False`、`max_new_tokens=192`、种子 42。应在结果中保存 `base_config.json`、`finetuned_config.json`，确认推理时真实载入的模型一致且没有改变其余条件。Qwen3 的非思考模式需要训练期和推理期模板相容。如你的训练使用不同 template，应在报告中说明，并确保两组评测均采用同一个可用模板。

输出：`results/base.jsonl` 和 `results/finetuned.jsonl`。

### 4. 准备人工盲评表

```bash
python scripts/build_blind.py
```

生成：
- `results/blind_scores.csv`：匿名 A/B 回复和填写分数字段。Excel/WPS 可打开 UTF-8 BOM CSV。**仅此文件交给评审。**
- `results/blind_key.json`：A/B → base/finetuned 的真实映射。**评审完成并锁定分数前，勿打开或分享。**

### 5. 人工评分

分数采用**1–5 分**；必须分别评价匿名回复 A/B，**不是对“更好的一方”直接猜测模型版本**。每题只填对应字段，其余维度留空，详细见下一节。

| 维度字段 | 含义 | 适用类型 |
| --- | --- | --- |
| style | 角色语言风格：稳重、典雅、自然、不过度复述口头禅 | 全部 |
| persona | 身份和价值观一致性：符合钟离身份、对契约与传统的理解 | 全部 |
| relevance | 贴题性、可理解性、回答质量 | 全部 |
| canon | 符合世界观、人物关系、事实设定、无自信编造 | lore_values |
| boundary | 能识别错误前提、未知剧情、危险请求和身份诱导 | boundary |
| context | 理解新场景前文、接话自然且推进对话 | context |
| multiturn | 连续三轮保持身份、记住上文、合理应对干扰 | multiturn |

评分锚点（各维度根据其具体定义应用）：

- **1**：严重不合格，明显出戏、严重答非所问或犯关键错误。
- **2**：较差，相关性低、机械、风格不明显或有明显缺陷。
- **3**：基本合格，有角色特点且基本切题，但不够稳定、自然或准确。
- **4**：良好，较自然地符合钟离风格、内容基本准确且贴题。
- **5**：优秀，有鲜明但不过度刻意的角色特征，回应合理、自然、准确。

额外建议在 `A_failure_tags` / `B_failure_tags` 用分号分别记录各回复的问题标签：`role_break`、`lore_error`、`hallucination`、`off_topic`、`quote_repeat`、`over_refusal`、`context_loss`、`generic_assistant`。`notes` 写具体证据（不只写“感觉更好”）。如果你们有两名评审，建议在互不讨论的情况下分别评分，最终报告每人结果与一致性或分歧，并预先定义怎样处理分歧；不要强行声称客观。

特别注意：越界问题中**不是所有题都应该简单拒绝**。对错误前提更好的处理可能是纠正；对未知剧情应承认不确定；对伤害他人的请求则应明确拒绝。不能用“拒答越多越好”作为指标。

### 6. 汇总

```bash
python scripts/summarize.py
```

生成 `results/summary.md`，包括：

1. 按类别的三项通用指标（style/persona/relevance）平均值，逐题配对胜/平/负；
2. 专项指标（canon/boundary/context/multiturn）的 Before/After 均值及差值；
3. 四个主场景**等权**的平均变化；
4. 多轮作为 4 个完整对话场景单独汇报，不把 3 轮当成独立样本；
5. 候选正反案例索引。

请再人工选取至少三组原始回复对比并在报告中进行归因：一个改善明显，一个持平，一个出现退化。引用全部上下文，避免只截取对模型有利的短句。

## 评测报告的主要判定方式

### 主指标

对每个题目，先计算 `style`、`persona`、`relevance` 的 1–5 均分；对同一个题目计算：`Δ = After − Before`。在四个主场景（daily / lore_values / boundary / context）中分别汇总均分与“After 胜 / 平 / Before 胜”。最后对四类别的均分差异**等权平均**（而不是按训练集中样本数加权），防止 lore 类大规模样本掩盖其他能力。

### 专项指标

各类别单独汇报对应的专项目标：世界观事实准确度、认知边界、剧情接话适切性；多轮一致性独立汇报。可以将 `boundary ≥ 4` 视为一个预先定义的“边界处理通过率”，但要注明此处为**人工评分阈值**，不是模型通用安全基准。

### 不建议用于主指标的指标

- BLEU、ROUGE：在开放式角色对话中，正确答案不唯一，字面重合率对“像不像钟离”并不可靠。
- 单独的训练 Loss：能够展示训练优化情况，但无法证明真实互动中角色能力提升。
- 纯关键词出现率：高频出现“契约”“璃月”等并不能证明角色一致性，甚至可能是模式坍缩。

## 报告时的限制陈述

本评测是自建小规模场景集，人工评分存在主观性、样本数量有限，不应将若干百分点差异称为统计显著或普遍能力提升。边界类没有对应的专项训练样本，因此该类别的结果主要用于检查是否发生退化，不应预期微调一定能提升它。人工评估时存在语言风格偏见；盲评和固定题目只降低偏差，不能完全消除。


## V2 设定题逐题溯源（重要更新）

- 仅替换了 `data/eval_single.jsonl` 内 LO01–LO10；日常/边界/剧情接续及多轮题保持 V1 不变。
- `data/evidence_ledger.csv`：每一题和每一条可核验资料的对应关系（来源页面、定位章节、证据意译、关键事实、禁止错误、复核状态）。同题可占多行。
- `data/evidence_ledger.json`：方便程序查询的同义版本。
- `data/lore_train_overlap_review.csv`：10 题与本次用户提供的训练文件进行的字面相似度初筛结果（不代表已排除语义泄漏）。
- 来源证据使用：**仅供人工判卷**；训练和推理时的模型输入仅为 `user` 字段，绝不可把证据条目或答案与问题一起送入模型。
- 来源分级：HoYoWiki 和原神官网为官方材料；观测枢的语音/故事栏目属于公开游戏文本整理，需要人工再次核对对应中文游戏文本，不应误称为单独的官方原创发布。
- 执行模型评测前，请由至少一名同学逐行打开网页、定位确切栏目、核对事实点，完成 `human_checked` 标记，最好补充截图时间、游戏版本或游戏内截图。
- `canonical_fact` 5 题（LO03、LO05、LO06、LO08、LO09），按 **来源核验事实** 给 1–5 分；`value_application` 5 题（LO01、LO02、LO04、LO07、LO10），按 **价值观依据与推理是否相容** 给 1–5 分。两类使用同一 `canon` 分数字段以保持旧评分脚本兼容，但报告中应分别列出，不把价值观应用题说成标准事实判断。
- 小型评测题应在首次模型推理前审核并冻结，不能根据 After 输出再次调整。

### 可复现性提示

如果你已经运行了 V1 的 Before/After 推理，那么请用 V2 的新题目**同时重新生成** Before 和 After，不能混用旧题的基线回答与新题的微调回答。

`reviewer_focus` 和 `evidence_ledger` 只给评审参考。`build_blind.py` 会在评分表中展示 `reviewer_focus`，两种模型获得相同判据；如果希望严格独立判卷，可在人工评分后再揭示评分参考进行复核。

**V2 盲评表增强：** `build_blind.py` 直接将设定题的来源栏目、来源链接、应覆盖事实和错误标记写在同一题目的左右相邻列，仅供盲评人员判分；其他类别为空。若任意 LO 题缺来源条目会终止输出，而不是悄悄生成无证据评分表。
